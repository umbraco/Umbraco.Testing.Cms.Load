ApiHelpers — CONSTRUCTION & AUTH  (THE CONTRACT lib/api.ts DEPENDS ON)
================================================================================
GUESSED (WRONG):  new UmbracoApiHelpers(request, baseUrl); api.login(user, pw)
REAL (VERIFIED):
    import { ApiHelpers } from '@umbraco-cms/acceptance-test-helpers';
    const api = new ApiHelpers(page);          // takes a Playwright PAGE
    await api.login.login(email, password);    // PKCE login via api.login (LoginApiHelper)

  - Constructor signature:  constructor(page: Page)
      * It needs a `Page`, NOT an `APIRequestContext`. All HTTP goes through
        `page.request.*`, and the auth token/cookies live in that page's
        request context after login. So tests must use the `page` fixture, not
        the `request` fixture.
  - baseUrl is a CLASS FIELD initialized from umbracoConfig at IMPORT time:
        baseUrl = umbracoConfig.environment.baseUrl
    It is NOT a constructor argument and cannot be overridden after import.

  CONFIG IS ENV-DRIVEN (dist/umbraco.config.js), read at module import:
        URL                    -> environment.baseUrl  (default https://localhost:44339)
        UMBRACO_USER_LOGIN     -> user.login           (default nge@umbraco.dk)
        UMBRACO_USER_PASSWORD  -> user.password         (default 1234567890)
        UMBRACO_MEMBER_LOGIN / UMBRACO_MEMBER_PASSWORD  -> member.*
    >>> Because these are read at IMPORT time, the run command MUST export `URL`
        (and the user vars) for baseUrl to point at the live server. Setting
        process.env.URL inside makeApi() is TOO LATE to affect api.baseUrl.
        For Task A1 the smoke run set BOTH our env.ts names AND the package's
        names:
          URL / UMBRACO_USER_LOGIN / UMBRACO_USER_PASSWORD
        Later pipeline wiring must export URL (= UMBRACO_BASE_URL) before node
        loads the package.
